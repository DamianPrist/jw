## 一、需求分析

### 1.1 功能需求

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 用户登录 | 用户通过昵称登录服务器，服务器校验昵称合法性（非空、长度 ≤ 20、不含空格/@/换行等特殊字符）和唯一性 |
| F2 | 用户登出 | 用户主动退出或异常断线时，服务器清理连接资源并广播下线通知给所有在线用户 |
| F3 | 公聊消息 | 用户发送的消息默认广播给所有在线用户（不含发送者自身） |
| F4 | 私聊消息 | 用户可与指定在线用户进行一对一私聊，支持多窗口并存；收到私聊消息时自动弹出对应窗口 |
| F5 | 在线用户列表 | 登录时获取全量在线用户列表，后续由服务器实时推送上线/下线增量更新 |
| F6 | 上下线通知 | 用户上线或下线时，系统向所有在线用户广播通知，公聊窗口显示系统消息 |

### 1.2 非功能需求

| 编号 | 需求 | 描述 |
|------|------|------|
| N1 | 并发处理 | 服务器需支持多客户端同时在线，每个客户端由独立线程处理 I/O |
| N2 | 实时性 | 消息应在发送后即时到达目标客户端（局域网环境下延迟 < 100ms） |
| N3 | 可靠性 | TCP 协议保证消息可靠传输；应用层通过 `\n` 分隔符解决粘包/半包问题 |
| N4 | 可用性 | 提供 tkinter 图形用户界面，操作直观；错误场景（连接失败、昵称冲突等）有明确弹窗提示 |
| N5 | 跨平台 | 纯 Python 标准库实现，兼容 Windows / Linux / macOS |

### 1.3 运行环境

- Python 3.6+
- 操作系统：Windows 10/11、Linux、macOS
- 网络：局域网内 TCP 互通

### 3.3 重要算法流程图 / 伪代码

#### 3.3.1 服务端消息处理主循环（handle_client）

```
算法: handle_client(sock, addr)

输入: 已 accept 的客户端 socket, 客户端地址
输出: 无 (循环处理直至断开)

1.  buf ← 空 bytearray
2.  authenticated ← False
3.  打印 "[连接] {addr}"
4.
5.  循环:
6.      data ← sock.recv(4096)
7.      若 data 为空 (连接关闭):
8.          跳出循环
9.
10.     buf.extend(data)
11.     messages ← unpack_from_buffer(buf)   // 提取所有完整 JSON
12.
13.     对 messages 中每条 msg:
14.         msg_type ← msg["type"]
15.
16.         若 NOT authenticated:
17.             若 msg_type == "login":
18.                 authenticated ← handle_login(sock, msg)
19.             继续下一轮
20.
21.         若 msg_type == "login":    继续     // 已登录忽略
22.         若 msg_type == "logout":   返回     // 退出循环
23.         若 msg_type == "broadcast": handle_broadcast(sock, msg)
24.         若 msg_type == "private":   handle_private(sock, msg)
25.
26. 最终:
27.     disconnect_sock(sock)   // 清理映射 + 广播下线 + 关闭 socket
```

#### 3.3.2 粘包/半包处理算法（unpack_from_buffer）

```
算法: unpack_from_buffer(buffer: bytearray) → list[dict]

输入: 接收缓冲区 (bytearray, 会被修改)
输出: 本次可解析的完整消息列表

1.  messages ← []
2.  循环:
3.      idx ← buffer.find(b'\n')        // 查找分隔符
4.      若 idx == -1:                   // 没有完整消息
5.          跳出循环
6.      若 idx > 64KB:                  // 超长消息, 丢弃
7.          删除 buffer[0..idx]
8.          继续
9.      raw ← buffer[0..idx]            // 取出分隔符之前的数据
10.     删除 buffer[0..idx+1]           // 从缓冲区移除 (含分隔符)
11.     若 raw 非空:
12.         尝试 JSON 解析 raw
13.         若成功且结果为 dict:
14.             messages.append(msg)
15.         若失败 (JSONDecodeError / UnicodeDecodeError):
16.             忽略 (丢弃损坏数据)
17. 返回 messages
```

**原理说明：** TCP 是字节流协议，没有消息边界。发送端每次 `send` 不一定对应接收端一次 `recv`。可能出现：
- **粘包**：多条消息在一次 `recv` 中到达，buffer 中可能包含多个 `\n`
- **半包**：一条消息被拆分在两次 `recv` 中，buffer 中可能没有 `\n`

解决方式：使用 `bytearray` 累积所有接收数据，以 `\n` 为分隔符循环提取完整 JSON 消息，剩余不完整片段留在 buffer 中等待后续数据。


### 3.4 通信协议设计

**消息格式：** JSON 文本，以 `\n` (0x0A) 结尾作为消息分隔符。

**客户端 → 服务端：**

| 消息类型 | JSON 格式 |
|----------|-----------|
| 登录 | `{"type":"login","nickname":"Alice"}` |
| 公聊 | `{"type":"broadcast","content":"Hello!"}` |
| 私聊 | `{"type":"private","to":"Bob","content":"Hi"}` |
| 登出 | `{"type":"logout"}` |

**服务端 → 客户端：**

| 消息类型 | JSON 格式 |
|----------|-----------|
| 登录成功 | `{"type":"login_ok","users":["Alice","Bob"]}` |
| 登录失败 | `{"type":"login_fail","reason":"昵称已存在"}` |
| 用户上线 | `{"type":"user_online","nickname":"Alice"}` |
| 用户下线 | `{"type":"user_offline","nickname":"Alice"}` |
| 公聊消息 | `{"type":"broadcast","from":"Alice","content":"Hello!"}` |
| 私聊消息 | `{"type":"private","from":"Alice","content":"Hi"}` |
| 错误消息 | `{"type":"error","reason":"用户不在线"}` |

## 四、实现

### 4.1 关键代码

#### 4.1.1 协议层 — 消息打包与解包（protocol.py）

```python
def pack_message(msg: dict[str, Any]) -> bytes:
    """将消息字典序列化为 JSON 并追加换行分隔符。"""
    body = json.dumps(msg, ensure_ascii=False)
    if len(body) > MAX_MESSAGE_LENGTH:
        raise ValueError(f"消息过长: {len(body)} bytes")
    return body.encode(ENCODING) + DELIMITER


def unpack_from_buffer(buffer: bytearray) -> list[dict[str, Any]]:
    """从接收缓冲区中提取所有完整的 JSON 消息。"""
    messages = []
    while True:
        idx = buffer.find(DELIMITER)
        if idx == -1:
            break
        if idx > MAX_MESSAGE_LENGTH:
            del buffer[:idx + 1]  # 超长消息，丢弃
            continue
        raw = bytes(buffer[:idx])
        del buffer[:idx + 1]
        if raw:
            try:
                msg = json.loads(raw.decode(ENCODING))
                if isinstance(msg, dict):
                    messages.append(msg)
            except (json.JSONDecodeError, UnicodeDecodeError):
                pass  # 丢弃损坏数据
    return messages
```

**设计要点：** 以 `\n` 为分隔符，使用 `bytearray.find()` 定位分隔符位置。循环切分，剩余不完整数据保留在缓冲区。同时解决了 TCP 粘包（多条消息在一次 recv 中到达）和半包（一条消息被拆分在多次 recv 中）问题。

#### 4.1.2 服务端 — 多线程并发处理（server.py）

```python
def main(host="0.0.0.0", port=9999):
    serversock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    serversock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    serversock.bind((host, port))
    serversock.listen(10)
    print(f"服务端启动: {host}:{port}", flush=True)

    try:
        while True:
            conn, addr = serversock.accept()
            t = threading.Thread(target=handle_client, args=(conn, addr), daemon=True)
            t.start()
    except KeyboardInterrupt:
        pass

    print("\n服务端关闭", flush=True)
    # 清理所有连接
    with lock:
        for sock in list(clients.keys()):
            try:
                sock.close()
            except OSError:
                pass
    serversock.close()
```

**设计要点：** 主线程阻塞在 `accept()`，每 accept 一个连接立即创建 daemon 线程处理。`threading.Lock` 保护 `clients` 和 `nick_to_sock` 两个共享字典。daemon 线程保证主线程退出时所有工作线程自动终止。

#### 4.1.3 客户端 — 双线程 + 队列消息路由（client.py）

```python
class _MessageRouter:
    """消息路由：接收线程 → Queue → 主线程定时轮询分发"""

    def __init__(self, sock, public_window):
        self.sock = sock
        self.public_window = public_window
        self.msg_queue = queue.Queue()
        self.running = True
        self.recv_thread = threading.Thread(target=self._receive_loop, daemon=True)

    def _receive_loop(self):
        buf = bytearray()
        while self.running:
            try:
                data = self.sock.recv(4096)
            except (ConnectionResetError, ConnectionAbortedError, OSError):
                data = b""
            if not data:
                self.msg_queue.put({"type": TYPE_DISCONNECTED})
                break
            buf.extend(data)
            for msg in unpack_from_buffer(buf):
                self.msg_queue.put(msg)

    def _poll_queue(self):
        try:
            while True:
                msg = self.msg_queue.get_nowait()
                self._dispatch(msg)
        except queue.Empty:
            pass
        if self.running:
            self.public_window.root.after(100, self._poll_queue)

    def _dispatch(self, msg):
        msg_type = msg.get("type", "")
        if msg_type == TYPE_PRIVATE:
            sender = msg.get("from", "")
            self.public_window.route_private_msg(sender, msg["content"])
        elif msg_type == TYPE_BROADCAST:
            self.public_window.append_message(f"[公聊] {msg['from']}: {msg['content']}")
        elif msg_type == TYPE_USER_ONLINE:
            self.public_window.user_listbox.insert(tk.END, msg["nickname"])
            self.public_window.append_message(f"[系统] {msg['nickname']} 上线了")
        elif msg_type == TYPE_USER_OFFLINE:
            self.public_window.remove_user_from_list(msg["nickname"])
            self.public_window.append_message(f"[系统] {msg['nickname']} 下线了")
        elif msg_type == TYPE_ERROR:
            self.public_window.append_message(f"[系统] 错误: {msg.get('reason', '')}")
        elif msg_type == TYPE_DISCONNECTED:
            self.public_window.append_message("[系统] 与服务器断开连接")
            self.public_window.set_disconnected()
```

**设计要点：**
- **线程分离**：接收线程负责 socket I/O，GUI 主线程负责 tkinter 渲染，两者仅通过 `queue.Queue` 通信
- **定时轮询**：`root.after(100, self._poll_queue)` 每 100ms 检查队列，将网络消息安全地注入 GUI 线程
- **私聊路由**：`_dispatch` 将 private 消息路由到 `PublicChatWindow.route_private_msg()`，自动查找或创建对应私聊窗口

```python
class PublicChatWindow:
    def open_private_chat(self, target):
        """打开或激活与指定用户的私聊窗口。"""
        if target in self.private_windows:
            pw = self.private_windows[target]
            if pw.root.winfo_exists():
                pw.root.deiconify()
                pw.root.lift()
                pw.input_entry.focus_set()
                return
            else:
                del self.private_windows[target]

        pw = PrivateChatWindow(
            self.sock, self.nickname, target,
            on_close=lambda t=target: self._on_private_closed(t)
        )
        self.private_windows[target] = pw

    def route_private_msg(self, sender, content):
        """收到私聊消息时，自动弹出或路由到对应窗口。"""
        if sender not in self.private_windows or \
           not self.private_windows[sender].root.winfo_exists():
            self.open_private_chat(sender)
        self.private_windows[sender].receive_message(sender, content)
```

**设计要点：**
- 私聊窗口通过 `private_windows: dict` 集中管理，以目标昵称为 key
- 双击在线用户 或 收到私聊消息 均可触发窗口创建
- 已存在的窗口自动激活（`deiconify` + `lift`），防止重复打开
- 窗口关闭时通过 `on_close` 回调清理字典中的引用
